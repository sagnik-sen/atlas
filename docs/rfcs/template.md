# RFC Template

## RFC: [Title]

**Status:** [Draft | In Review | Accepted | Rejected]  
**Author:** [Name or GitHub handle]  
**Date:** [YYYY-MM-DD]

## Summary

One paragraph that explains the proposal to someone who hasn't read anything else.

## Motivation

Why are we doing this? What problem does it solve? What use case does it enable?

## Design

The technical proposal. Be specific. Include:
- Data model changes (node types, edge types, properties)
- API changes (new queries, changed signatures)
- Pipeline changes (new extractors, changed extraction flow)
- Format/serialization changes

Code sketches are welcome. The more concrete, the more useful the feedback.

## Example Usage

Show how a developer would use this. Concrete examples reveal design flaws that abstract descriptions hide.

## Alternatives Considered

What else could we do? Why is this approach better?

## Drawbacks

Every design has downsides. Be honest about them. What's the cost of this change? What's the migration burden? What constraints does it impose?

## Open Questions

What isn't resolved yet? What needs more investigation before we can decide?
